**[[Agile Software Development]]**
![[extreme programming cycle.png]]

| Principle or Pracitce       | Desc                                                                                                                                                                         |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Incremental Planning        | Reqs are recorded on story cards and the stories to be included in a release are determined by the time available and their relative priority. Devs break stories into Tasks |
| Small releases              | The min useful set of functionality that provides business value is developed first. Releases are frequent and incrementally add functionality to the first release          |
| Simple design               | Enough design is carried out to meet the current reqs and no more                                                                                                            |
| Test-first dev              | An automated unit test framework is used to write tests for a new piece of functionality before it is implemented.                                                           |
| Refactoring                 | All devs are expected to refactor the code continuously as soon as possible code improv. are found.                                                                          |
| Pair programming            | Devs work in pairs, checking each other code                                                                                                                                 |
| Collective ownership        | The pairs of dev work on all areas of the system, so that no islands of expertise develop and all the devs take responsibility for all the code. Anyone can change anything  |
| Continuous Integration (CI) | As soon as the task is closed, it is integrated into the whole system. After integration, all the unit tests must pass                                                       |
| Sustainable pace            | Large amounts of overtime are not acceptable as the net effect is often to reduce code quality and medium term productivity                                                  |
| On-site customer            | Customer should be available full time for the use of XP team. In XP team, customer is a member and is responsible for bringing sys reqs to the team for imp.                |
Consequently, while agile development uses practices from XP, the method as originally
defined is not widely used.
